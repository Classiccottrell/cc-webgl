## 2. TypeScript Interfaces / Types (beyond what's given)

```ts
// types.ts

export type QualityTier = 'FULL' | 'REDUCED' | 'FALLBACK';

export interface QualityProfile {
  readonly tier: QualityTier;
  readonly maxDPR: number;          // FULL: 2.0, REDUCED: 1.0, FALLBACK: n/a
  readonly postProcessing: boolean; // FULL: true, REDUCED: false, FALLBACK: n/a
  readonly shadows: boolean;        // FULL: true (standard), REDUCED: false, FALLBACK: n/a
  readonly particleScale: number;   // multiplier on base particle/mesh density, 0..1
  readonly throttleHidden: boolean; // REDUCED: true — throttle background execution
}

export interface FrameState {
  readonly dt: number;              // seconds, clamped (e.g. max 0.1)
  readonly elapsed: number;         // seconds since scheduler start
  readonly frame: number;           // monotonically incrementing frame count
  readonly now: number;             // performance.now() at this tick
}

export interface ViewportState {
  readonly width: number;
  readonly height: number;
  readonly dpr: number;
  readonly aspect: number;
}

// Discriminator rule (closes the doc's "(?)" on ScrollBridge/AnimationBridge):
// SceneContext requires `scroll: ScrollState` unconditionally -> ScrollBridge is
// CORE and mandatory, native-scroll by default, Lenis injectable as an optional driver.
// GSAP appears nowhere in the runtime contracts -> AnimationBridge is OPTIONAL,
// lazily imported, activated only if a consumer calls bridge.attach(timeline).

export interface ScrollDriver {
  start(onUpdate: (raw: { y: number; timestamp: number }) => void): void;
  stop(): void;
}

// FALLBACK / SceneContext resolution (closes the doc's ambiguity):
// SceneContext.renderer stays non-optional, exactly as specified. SceneManager
// NEVER constructs a SceneContext or calls Scene.init in FALLBACK tier. On
// FALLBACK, ErrorBoundary mounts the DOM/SVG fallback directly and Scene is
// never instantiated. This keeps the given interface literal instead of
// making `renderer` optional.
```

### ResourceRegistry API

```ts
export interface ResourceRegistry {
  // GPU resources — typed overloads, each stores original + disposer
  track(resource: THREE.BufferGeometry): void;
  track(resource: THREE.Material): void;
  track(resource: THREE.Texture): void;
  track(resource: THREE.WebGLRenderTarget): void;
  track(resource: THREE.Object3D): void;      // traverses, tracks geometry+material+textures on dispose
  // CPU escape hatch — anything with no .dispose(): listeners, object URLs, observers
  track(disposer: () => void): void;

  untrack(resource: unknown): void;            // remove without disposing (ownership transfer)
  disposeAll(): void;                           // called by SceneManager.dispose()
  report(): { kind: string; count: number }[];  // dev-mode audit — makes "audited disposal" verifiable
}
```

### AssetLoader API

```ts
export interface LoadOptions {
  signal?: AbortSignal;                          // cancellation
  onProgress?: (loaded: number, total: number) => void;
  priority?: 'high' | 'low';
}

export interface AssetLoader {
  loadGLTF(url: string, opts?: LoadOptions): Promise<GLTF>;
  loadEnvironment(source: THREE.Scene | string, opts?: LoadOptions): Promise<{ texture: THREE.Texture; dispose(): void }>;
  loadTexture(url: string, opts?: LoadOptions): Promise<THREE.Texture>;
  loadFont(url: string, opts?: LoadOptions): Promise<Font>;
  cancel(url: string): void;
  clearCache(): void;
  readonly memoryBudgetBytes: number;             // safety ceiling; loader rejects/evicts past this
}
```

All loader results are cache-keyed by URL; repeated `loadX(url)` calls dedupe in-flight
promises. Caller is responsible for `resources.track()`-ing the returned GPU objects —
AssetLoader does not auto-register into a registry (keeps modules decoupled).

## 5. Single-Loop / Phase-Order Rule

`FrameScheduler` owns the **only** `requestAnimationFrame` call in the package.
`ResizeManager`'s "batch to next frame" means it enqueues its resize evaluation into
`FrameScheduler`'s queue — it does not run its own rAF.

Per-tick phase order, fixed:
```
input → scroll → animation (GSAP tick, if AnimationBridge attached) → scene.update(frame) → render
```

`document.visibilitychange` → scheduler pauses (no ticks fire; do not zero dt on
resume, reset `lastTime` instead to avoid a giant dt spike). `dt` is clamped (source
constant: 0.1s max, matches Mascot3D L131).

> The canonical starting point for a new project. Fill every section before any

## Goal
A lightweight, framework-agnostic TypeScript WebGL/Three.js foundation shared across
future interactive-site projects (Perspective/Shotforge, Forma/ShapeLab, Route
Grapher, Fictional Architecture Reconstructions). Solves rendering lifecycle, input
normalization, scroll authority, performance tiering, accessibility fallbacks, asset

- No project-specific styling, copy, or business logic (zero brand leaks).
- No React dependency in core — React support is an optional adapter subpath only.

- Not a full post-processing / VFX framework — quality tiers gate effects, they don't
  implement them.

- `three` is a peerDependency, not a dependency — never bundle or duplicate THREE.
- Single `requestAnimationFrame` loop for the whole package (FrameScheduler owns it).
- All GPU/CPU resources must have an audited disposal path via ResourceRegistry.
- No user-agent sniffing for quality-tier detection.
- Must run standalone via `file:../cc-webgl` from sibling `Projects/` folders; no root
  workspace manifest assumed.

- TypeScript, ESM only.
- three.js (peer dependency).
- Vite (lib mode, multi-entry: `.` and `./react`) for build.
- vitest + happy-dom for unit tests (FrameScheduler, ResourceRegistry, EventBus,
